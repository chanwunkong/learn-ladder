# 後中化學：章節寫作標準

以「配位化學」一章為範本整理（2026-10-29）。之後每一章都照這份標準重寫。

## 1. 範圍：歷屆考過的都要教到
- 用 `python3 -I analysis/exam/dump.py <主題代碼>` 列出這個主題的全部歷屆題。
- 逐題檢查：解這題需要的觀念，本章內文有沒有教。沒教到的，先補進內文，再出相似題。
- 一次只做一章，做完發佈，再做下一章。

## 2. 每一節的寫法
- 標題用一個問題，例如「硫酸銅為什麼是藍的？」。
- 內文 1–3 段短文字，主角是下面的圖。
- 用正式名詞，**不用比喻**（例如不用「爬樓梯」「擠一擠」「握手」「吃掉顏色」）。

## 3. 能畫成圖的就不用文字或表格
- 判斷方式：讀者需要比較、計算、想像空間排列、或看一個量怎麼隨另一個量變化 → 做成圖。
- 圖由讀者自己操作：切換、拖動滑桿、點選、轉動模型。**不做自動播放的動畫。**
- 例子（配位化學）：
  - 配位基的牙數：畫出結構，圈出配位原子。
  - d 軌域分裂：選形狀（八面體、四面體、平面四方、直線形）、拖近配位基，看能階怎麼分開。
  - 異構物數目：由電腦列出全部排法並標出鏡像對，讀者自己數。
  - 價鍵混成：軌域格子，看配位基電子對放進哪些空軌域。
- 可以保留文字的情況：純記憶的名稱清單（如 -ate 的拉丁字根）、一行總整理、應用敘述。

## 4. 公式長在圖上
- 公式的每一項都要對應到圖上看得到的長度、位置或數字。
- 圖下方的算式要即時代入目前的狀態，例如：
  - 長條圖的長度就是總能量：(eg 電子數) × Δo + (成對數) × P。
  - Δo = hc/λ 畫成曲線，點跟著選擇移動，下方算式代入數字。
  - 電荷算式：Co（x）+ 5 × NH₃（0）+ Cl⁻（−1）= +2 → x = +3。

## 5. 視覺規則
- **整體和成分不能用同一種樣式。** 例：錯離子畫在方括號框裡、用實線連在金屬上；外界離子畫在框外、用虛線圓。
- 同一個東西在不同地方用同一個顏色。例：配位基在結構圖和 IUPAC 名稱裡同色。
- 能量升高用紅、降低用藍；金屬自己的電子用藍、配位基提供的電子用紅。
- 手機寬度（360px）也要看得清楚：寬圖拆成兩張可以上下排列的圖。
- 深色模式要能看清楚：有填色的圓或方塊，文字顏色要固定，不能跟著主題變淡。

## 6. 題目
- 章末「確認理解」：檢查本章觀念，每題附解說；有對應的圖時加「在圖上看」。
- 「歷屆考題相似題」：依歷屆題的考法自己出題，換掉化合物和數字，不轉載原題；每題標註「仿 學校 學年 第 X 題」。
- 每次作答都自動記錄到練習紀錄（日期、時間、章節、題目、作答次數、結果）。

## 7. 正確性
- 數據要有來源（教科書、CRC、OpenStax 等）；不確定的數據寧可不寫。
- 會隨教科書不同而略有差異的數值，標成「約」或註明來源。

## 8. 發佈前檢查
- `bash tests/chem/smoke.sh`：所有按鈕都按過、文字不重疊、不超出圖框、名詞都有連結、沒有錯誤。
- 實際看桌機和手機畫面各一次。
- `bash tests/chem/publish.sh "說明"`，再更新預覽版。

## 題庫更新與練習紀錄

- 練習紀錄用「題目識別碼」對應題目（章節 id + 題型 + 題目文字的雜湊），並存一份題目文字快照；插入、刪除、重排題目都不會讓舊紀錄錯位或消失。
- 只改錯字、不想讓舊紀錄斷開時，在題目上加 `id: '原本的識別碼'`（識別碼列在 tests/chem/qids.txt）。
- 新題一律加在 quiz／exam 陣列中；同一章內題型相同的題目文字不能重複（tests/chem/qid.test.js 會擋下）。
- 登入後紀錄與雲端取聯集合併（users/{uid}/settings/chemLog），任何一邊都不會刪掉另一邊的紀錄；本機最多保留 20000 筆。

## 拆解步驟（一步一步來）

- 需要推理或計算的題目，在 `src/chem/st/章id.js` 寫拆解步驟：`STEPS[章id] = { "q或x:識別碼": [[問題, 正解, 誤1, 誤2, 說明], ...] }`。識別碼與練習紀錄相同，題目改寫後步驟會對不到，`tests/chem/steps.test.js` 會提醒。
- 每步只問一個小判斷，順序就是解題的思路（先找出用什麼原理，再代入，最後比較）。
- 答錯主題目時自動打開步驟；步驟答錯只說「再想想」，不給答案；答對才顯示說明並進下一步，最後回原題再選一次。
- 純記憶題（定義、人名、用途）不寫步驟。
- 撰寫工具：`node tools/chem/dumpq.js 章id` 列題、`node tools/chem/addst.js 章id 檔案` 寫入（每行 `q3｜問題｜正解｜誤1｜誤2｜說明`）。

## 名詞、符號與公式都要講清楚（2026-10-31 使用者要求）

- 內文第一次用到的名詞或縮寫（IR、官能基、eV、Å、鍵級…）要用一句中文說明它是什麼；不能只丟名詞。互動圖、卡片裡出現的名詞，內文要先教過。
- 每個公式（`<p class="eq">`）下面緊接符號表 `<dl class="sym"><div><dt>符號</dt><dd>中文意思、單位、常用數值</dd></div>…</dl>`，不用點就看得到。
- 公式與重要數字旁標一個標籤：`<span class="tg must">要背</span>`（考試不給，要記住）、`<span class="tg derive">會推</span>`（由其他公式或常數推出，例如 119,600、1240）、`<span class="tg given">卷上會給</span>`（題目或卷首常數表會提供）。每章第一次出現標籤時，用 `<p class="tglegend">` 說明三種標籤的意思。
- 換算捷徑要寫出它怎麼來，讓學生忘了可以自己重算。
- 「拖動滑桿」「點選按鈕」等操作說明必須和互動圖實際的樣子一致；互動圖名稱不可重複（smoke.sh 會擋）。

## 什麼概念要做互動圖（2026-10-31 與使用者訂定）

符合任一條就要有可操作的圖：
1. **公式**：每條標「要背」或「會推」的公式，至少有一張圖能拖動它的每個變數，結果立刻顯示在圖上（公式長在圖上）。
2. **看不見的東西**：波、電子、軌域、節點、分子形狀、立體構型、遮蔽。
3. **會隨條件或時間改變的過程**：滴定、反應進行、機構步驟、平衡移動、躍遷。
4. **考題要比較或排序的一組東西**：能切換、並排比較（譜線系、沸點、酸性、鍵角、電子親和力）。

不做圖：定義與名稱、歷史、純記憶清單（人名、俗名、試劑縮寫、焰色）、單一數字。

檢查方法：逐節列出概念 → 依上面四條分類 → 對照現有圖是否真的能操作那個變數 → 缺的列清單與使用者討論後再做。第一章（原子結構）已依此補齊；其他章尚未盤點。

## 公式裡的數字常數（2026-11-01，問題 E）
- 公式中出現的每個數字（13.6、0.529、1240、119,600、0.0821、8.314、1.0 × 10⁻¹⁴…）都要在符號表裡說明：它是什麼、從哪裡來（實驗值，或由哪些常數相乘換算）、考試要背還是卷上會給。
- 公式裡的乘數與次方（× Z²、÷ n²）也要用一句話說明為什麼是這個形式。
- 由別的數字推出來的（pH + pOH = 14 來自 Kw）要寫出推導，告訴讀者「這不是另一個要背的數字」。
- 一個 `.eq` 只放一條公式，各自標 要背／會推／卷上會給；不要把幾條公式擠在同一行（手機會從中間斷開）。

## 例外一定要說原因（2026-11-01，問題 F）
- 寫到「例外」「特例」「反常」，或內容其實違反前面的規則（例如游離能的凹陷），下一句一定是**為什麼一般規則在這裡不成立**，用本章或前面章節學過的概念解釋。
- 「較穩定」「比較容易」不算原因，要說明為什麼穩定、為什麼容易（例如：4s 與 3d 能量接近＋交換能；s 軌域穿透）。
- 題目解析裡提到例外，也要給同樣的原因，不能只寫「是例外」。

## 互動圖的版面（2026-11-01，問題 A、B）
- **拖動不跑版**：數值卡用共用的 `.cards` 格線，欄數只由畫面寬度決定；數值卡放在會改變長度的文字上面；可有可無的卡改成顯示「—」，不要讓卡片數量增減；數字太長就把單位移到卡片標題。
- **控制項一組一行**：每一組選擇用 `ctl(標籤, 選項)` 包成一個單位（標籤在上、選項在下），不可把「文字標籤＋一串按鈕」直接丟進 `.w-row`；按鈕組一律用 `seg()`／`segX()`，不要手寫。下拉選單本身含標籤（`label.sel`），可以幾個放同一列。
- **選項數量固定**：會隨其他選擇改變的選項（例如 mℓ 隨 ℓ 改變），一律顯示最大數量，不能選的變灰（`segX` 的第四個參數），不能讓按鈕消失或增加。

## 互動圖的內容：看得到、看得懂（2026-11-01，問題 C、D）
- **選到的東西一定在圖上**：圖的座標範圍要跟著選項走（例如光譜依系列切換紫外、可見、紅外的範圍），不能寫死成其中一種情況；標題、軸標籤也要跟著改。目前選取的元素加上 `data-cur="說明"`，smoke 會檢查它在圖框裡。
- **選到的東西一定有標籤，而且明顯**：起點、終點、選取的線都要有文字標籤（名稱＋數值），粗細或顏色要和其他元素明顯不同；標籤太擠時用避讓（往下推＋細線連回），不能只標一部分。
- **照比例畫但擠在一起時**：保留真實比例，但放大選取的那一段，並用文字說明「已放大、哪些在範圍外」。
- **底色不能像資料**：連續的色帶用漸層，不要用一條條小方塊（會被看成譜線或資料點）。

## 一節一頁，題目放在所屬小節（2026-11-01，S6）
- 章節頁分成：概覽頁（小節清單、讀過標記、各節練習進度）→ 每一節一頁（說明 → 互動圖 → 「看懂了」→ 這一節的練習 → 下一節）→ 綜合練習（只有跨好幾節的題目才放這裡，沒有就不出現）。
- 章節 id 加進 `app.js` 的 `PAGED` 就會改成這個版面；smoke 會自動逐頁測試。
- 每一題都要屬於一節：題目寫 `s: 第幾節`；沒寫的話依「在圖上看」連到的互動圖判斷。兩者都沒有的才進綜合練習，所以分節時要逐題確認。
- 每節頁面先顯示 3 題（章末基本題優先，再來是歷屆相似題），其餘折疊在「這一節還有 N 題」。
- 頁首有章內導覽（回概覽、第幾節、上一節／下一節、換章）；最後一節的按鈕通往綜合練習或下一章。「在圖上看」之後出現「回到剛才的題目」。

## 測試（2026-11-01）
- `bash tests/chem/smoke.sh` 預設電腦寬度；`SMOKE_W=390` 測手機寬度；`ONLY=章節id` 只測一章。發佈前兩種寬度都要過。
- 全部章節都檢查：圖中文字不重疊、不超出圖框。
- 只對 `tests/chem/strict.txt` 列出的章節（已依上面新規則修過）檢查：數值卡拖動不跳、文字不截斷、控制項分組、選項數量固定、`data-cur` 在圖上。每修完一章，把章節 id 加進 strict.txt，並更新 `章節檢查表.md`。
