## A. 版面隨內容長度改變（拖動時跑版）

**症狀**：「一道光」拖動波長時，「紅」變成「紅外光（看不見）」，數值卡重新排列，下面整段被推動。

**原因**：數值卡容器 `.cards` 用 flex-wrap，一列放幾張卡由「卡裡文字多長」決定。文字一變，換行位置就變。同一類：卡片數量隨選擇增減（電子組態的「等電子」卡）、會變長的文字放在卡片上方（濃度換算的計算式）。

**全站同類**：所有用 `card()` 的互動圖（共用樣式，一處改全站生效）。拖動時仍會跳的另外 3 個：atom/econf、stoich/concconv、atom/emspec（數字太長被截斷）。

**修正**（已在本機完成，尚未發佈）：
- `.cards` 改成固定格線：手機固定 2 欄、電腦依寬度；數字不換行、字級隨螢幕縮放。
- 可有可無的卡改成固定顯示（沒有就顯示「—」）。
- 數值卡放在會變長的文字上方。

**防止**：smoke 測試新增「拖滑桿時數值卡位置與大小不可改變、文字不可被截斷」，並在手機寬度與電腦寬度各跑一次（目前全部通過）。

## B. 控制項沒有分組：好幾組選擇擠在同一列

**症狀**：量子數圖的 n、ℓ、mℓ 三組按鈕擠成一團，標籤「ℓ」在第一行尾，它的按鈕跑到第二行；換 ℓ 時 mℓ 按鈕數量改變，整列重排。

**原因**：
1. 這類控制是「一個文字標籤＋一串按鈕」直接丟進同一個 flex 列，沒有包成一組，換行時標籤和按鈕會被拆開。
2. 已有共用元件 `seg()`，但部分互動圖沒用它，自己手寫按鈕，所以規則不一致。
3. 選項數量會變的按鈕列（mℓ 有 1、3、5、7 個）放在其他控制同一列，數量一變，整列跟著重排。

**全站同類**（手機寬度掃描）：
- 標籤和它的按鈕被拆到不同行（8）：acid-base/species、atom/qn、atom/radial、bonding/fc、kinetics/ratelaw、org-acid/pkaeq、thermo/gibbs、vsepr/vsepr
- 好幾組按鈕直接擠在同一列、沒有分組（5）：atom/qn、atom/radial、bonding/fc、kinetics/ratelaw、vsepr/vsepr
- 一列塞 3 組以上的控制（3）：atom/hspec、gas/maxwell、naming/ez
- 選項數量隨其他選擇改變（7）：atom/qn、biomol/aaside、org-acid/subst、rxn/cleave、spectro/nmr、vsepr/fcharge、vsepr/vsepr
- 另有 37 個互動圖的控制列在手機上折成多行、64 個按鈕組折成多行。多數只是選項多（例如預設情境按鈕），不算錯，但要逐一看是否需要分組。

**修正方式**：
- 每一組選擇做成一個單位：「標籤＋按鈕」包在一起，一組一行（手機）；不再手寫散按鈕，一律用共用元件。
- 數量會變的選項（mℓ）單獨一行，並預留最大數量的空間（不能選的變灰，而不是消失）。

**防止**：寫作標準加一條；smoke 測試加「標籤與按鈕同一行」「選項數量不變」兩項檢查。

## C. 圖的顯示範圍固定，選到範圍外就看不到

**症狀**：氫原子能階圖選「萊曼系」或「帕申系」時，下面的光譜只畫可見光 380–750 nm，選到的那條線根本不在圖上；標題卻固定寫「巴耳末系（掉到 n = 2）」。

**原因**：圖的範圍寫死成一種情況（可見光、巴耳末系），沒有隨選項調整，也沒有提示「這條線在範圍外」。

**全站同類**：無法自動判斷，需要逐一檢查「圖的座標範圍」是否涵蓋所有選項。已確認：atom/hspec。待查：所有有固定座標範圍、又有選單或預設按鈕的圖。

**修正方式**：範圍隨選項切換（紫外、可見、紅外各自的範圍），或保留全範圍並標出選到的線；標題跟著選項改。

**防止**：smoke 加「選到的值必須畫在圖內」（每個圖標記目前選取的元素，測試檢查它在圖框裡）。

## D. 照真實比例畫，擠在一起的部分沒標示

**症狀**：能階圖 n = 4、5、6、7 擠在頂端幾乎重疊；選了 n = 5 卻沒有標 n = 5，箭頭從哪一條出發看不出來；n = 2 到 n = 1 之間一大片空白。

**原因**：能量照真實比例畫是對的，但只標了 n ≤ 3，選取中的能階沒有保證一定被標出來；擠在一起的部分沒有放大或另外標示。

**全站同類**：需要逐一檢查「選取中的元素是否一定有標籤、是否清楚突出」。光譜圖選取的線只比其他線粗一點，也屬於這類（重點不夠突出）。

**修正方式**：選取中的起點與終點一定標名稱與能量；擠在一起的區域用放大框或錯開標籤；選取的線加標註，不只是加粗。

**防止**：寫作標準：「目前選取的東西一定要有文字標籤，並且和其他元素有明顯差異」。

## E. 公式裡的數字沒有說明來源；多條公式擠一行

**症狀**：13.6 eV、0.529 Å 只說是什麼，沒說從哪來；三條公式放在同一格，手機從中間斷開（「rₙ =」一行、「0.529 Å…」下一行）。

**原因**：寫作標準只要求解釋「符號」，沒有要求解釋「數字常數」。

**全站同類**：檢查了 31 章所有公式中的數字。1240、119,600、0.0592、0.693、R 已有說明；缺的是 13.6、0.529（atom）、Kw 的 1.0 × 10⁻¹⁴ 與 14、滴定 K ≈ 1.8 × 10⁹（acid-base）。多條公式擠同一格：10 章共 25 處。

**修正**（已在本機完成，尚未發佈）：補上來源（實驗值或由哪些常數算出、要背還是卷上會給），× Z²、÷ n² 說明為什麼；一格只放一條公式，各自標「要背／會推」。寫作標準已加「公式裡的數字常數」一節。

## F. 規則的例外只說「例外、要背」，沒說為什麼

**症狀**：「Cr、Mo 是 d⁵s¹，Cu、Ag、Au 是 d¹⁰s¹（半滿、全滿的 d 副層較穩定）」，沒有說為什麼較穩定，學習變成死背。

**原因**：寫作標準沒有要求例外要附理由；「較穩定」被當成解釋，其實只是換句話說。

**全站同類**（搜尋「例外、特例、不符合、反常」等）：
- atom：Cr／Mo／Cu／Ag／Au／Pd 的電子組態，內文與 3 題解析都只寫「較穩定」。要補：4s 和 3d 能量非常接近，移一個電子的代價很小；半滿或全滿時，同自旋電子可以互相交換位置（交換能）而降低能量，電子之間的排斥也較平均，收益大於代價。
- stereo：FCH₂CH₂F 偏好間扭式（gauche effect）只寫了名稱。要補原因（C–H 鍵電子推向相鄰 C–F 反鍵軌域的超共軛，在間扭式時兩者剛好反式對齊）。
- stereo：半胱胺酸是 R —— 已說明原因（CH₂SH 的 S 原子序大於 O，優先順序改變），這種寫法是對的。
- 還要另外檢查：沒有用「例外」兩字，但內容其實是例外的地方（例如 N 的游離能大於 O、Be > B、H₂O 沸點特別高），確認每一處都說了原因。

**修正方式**：每一個例外都要說明「一般規則為什麼在這裡不成立」，用前面學過的概念解釋；不能只用「較穩定」。能畫圖的（例如 3d／4s 能量接近、交換能）做成互動圖。

**防止**：寫作標準加一條：「凡是說『例外』，下一句一定是原因；『較穩定』不算原因，要說為什麼穩定」。

## 共同的根本原因

1. **只在電腦寬度測試**：smoke 原本只用 1100 px 寬度，手機上的跑版、標籤被拆開都測不到。以後手機與電腦兩種寬度都要測。
2. **測試只檢查「有沒有壞」，沒檢查「看不看得懂」**：文字重疊、超出圖框測得到，但「選到的東西不在圖上」「標籤和按鈕被拆開」測不到。要把這些變成自動檢查。
3. **寫作標準少了幾條**：數字常數要說明來源、例外要附理由、選取中的元素一定要標示、控制項一組一行。

## 建議修正順序

1. 發佈 A、E（已完成、測試通過）。
2. 寫作標準加入 B、C、D、F 的規則，smoke 加入對應的自動檢查。
3. 依檢查結果逐章修：先修 B 的 8＋5＋3＋7 個互動圖，再逐圖檢查 C、D，最後補 F 的例外理由。
