# 後中化學：章節寫作標準

最後整理：2026-11-07（把 2026-10-29 起分散加入的規則合併成一份，以 2026-11-07 的決定為準）。每一章重寫都照這份做；和使用者協作的流程見專案根目錄 `CLAUDE.md`。

第一章的教訓：初版的問題不是缺內容，而是「做了圖但看不懂」「公式的來源看不懂、只能死背」「名詞突然冒出來」。原因是只檢查「有沒有涵蓋考點、有沒有互動」，沒檢查「一句一句讀下來懂不懂」。

## 1. 流程（每章相同）

1. **先查歷屆題，確認範圍**：`python3 -I analysis/exam/dump.py <主題代碼>` 列出這個主題的全部歷屆題，逐題列出解題需要的觀念與名詞。這一步是寫作者自己用來決定要教什麼，**不寫進課文**。
2. **逐節寫方案給使用者確認**：每一節寫「推理鏈大綱」（每一步說什麼、怎麼接上一步）與「圖的設計」（畫什麼、怎麼操作、看到什麼變化）。存成 `analysis/第N章-S8-圖設計.md`。使用者確認後才寫程式。
3. **寫程式，通過測試後直接發佈**（第 10 節），不用再問一次。
4. **逐題核對**：這一節的每一題，答案需要的觀念與名詞（包括選項裡的用詞，例如「能階」），課文都教到了；沒教到就補進課文。
5. **手機截圖逐節自查**：只看課文和圖，新手說得出這一節的答案嗎？有沒有比課本插圖更難懂？有沒有考試不需要的資訊？
6. **使用者試讀**：看不懂的地方先依原因分類（不要看到一個修一個），提出改法、確認後再修，修完把新規則寫回本標準。

## 2. 講解：一條推理鏈

1. **每一句都承接上一句**：由上一句推出，或是遇到一個真實現象，舊的想法解釋不了，才引出新概念（例：光只當成波解釋不了光電效應 → 光子、E = hν）。不可以先丟規則再補理由。
2. **課文不提考題**：不寫「因為要考所以學」，也不寫具體考題或出處（「義守 108」等）。考題只出現在每節的練習。
3. **標題用一個問題**（例：「硫酸銅為什麼是藍的？」），整節的推理鏈就是在回答它；最後一句可以引出下一節的問題。
4. **抽象模型先說它是什麼**：第一次用模型（箱中粒子、波耳模型、VSEPR…）時，先說它是假想的還是真實的、每個符號對應真實世界的什麼（例：L 是電子能活動的範圍，不是半徑）、為什麼要這樣簡化、在哪裡是真的（例：共軛分子的碳鏈）。模型放在它真正被用到的章節，不要放在讓人誤會的地方。
5. **名詞與符號第一次出現就當場定義**，或指回前面教過的那一節。課文、圖、卡片、按鈕、題目選項裡用到的名詞都算。縮寫（IR、eV、Å…）也要用一句中文說明。
6. **真實例子與歷史**：用真實的物質、現象或實驗說明（例：1905 年光電效應、1927 年電子繞射），**不用比喻**（不用「爬樓梯」「擠一擠」「握手」「跳繩」）。
7. **例外一定說原因**：寫到「例外」「特例」，或內容違反前面的規則時，下一句一定說明為什麼一般規則在這裡不成立。「較穩定」「比較容易」不算原因（例：W 不搬電子，因為 6s 被拉低、6s 和 5d 差距變大，半滿的好處付不起）。
8. **前面學過的觀念要用時**，用一句話帶回來並指出是哪一節。
9. **用詞統一**：用正式名詞；頁面結構只用「章」「節」。
10. **句子簡短**（2026-11-08 使用者：「中文說明稍顯複雜囉嗦」）：一句只講一件事，超過一個「，……，所以……」就拆開；括號裡的補充能刪就刪，不能刪就獨立成一句；刪掉「也就是」「其實」「就是」「這時」等贅字；同一件事在說明、圖下綠框、整理裡只講一次；一段三句以內，並列的幾件事改成條列。
11. **不寫贅詞**（2026-11-08 使用者：「是贅詞不是專有名詞，例如『不用死背』」）：不寫提醒式的話（「不用死背」「要記住」「考試不考」「用下面的圖推」）；不寫不影響理解的補充（「這一格第 1 個」「這是依真實能量排出來的記憶方法」「顏色最清楚的那個」）。**圖下的綠框和說明只說這一步的結果**，不重複課文已經講過的讀法、順序或原因。
12. **順序不跳**（2026-11-11 使用者試讀第二章第 1 節：「跳來跳去」）：圖上會出現的每樣東西（每條線的顏色、箭頭的意思）在圖上方一次講完，不在圖後面才回頭解釋；圖上有的量（例：箭頭代表的力）和課文的量（位能）之間的關係要先教；要出公式前先說為什麼需要它（例：「要算出鍵長在哪裡，就要把曲線寫成式子」）；標籤說明放在第一個標籤之前。
13. **不用沒教過的數學**：不用微分等課程沒教的工具推公式。改用高中學過的數學（例：令 x = 1/r⁶，位能變成拋物線，最低點用頂點公式），圖用來驗證推導，不可以只叫讀者「在圖上看到」一個數字而不說它從哪裡來（2026-11-12 使用者：「這是哪裡推導出來的」）。名詞不要和別的量只差一個字（排斥項是能量、排斥力是箭頭），第一次出現要說清楚是哪一種量。

## 3. 公式

1. **用課本和詳解的寫法，要求的量放左邊**：E = hν、E = hc/λ、λ = h/(mv)、Eₙ = −13.6 eV × Z²/n²、Eₙ = n²h²/(8mL²)。先看歷屆題用什麼形式。
2. **推導只用「代入」，不讓讀者移項**：前一條公式就寫成下一步要代入的形式（例：先給 ν = c/λ，再代入 E = hν 得到 E = hc/λ）。真的需要反過來求時，只用一招「兩個量互換位置」（λ = hc/E、mv = h/λ），並說明這是同一招。
3. **完整推導**：從讀者已經懂的東西一步一步推到公式，每一步一句話說明意思。不可以寫「把 λ 代進波的能量……」而「波的能量」從沒教過。推得出來的公式標「會推」，讀者記的是推導。
4. **一個公式框（`.eq`）只放一條公式、一個等號**，中間形式寫在文字或推導步驟裡。
5. **標籤**：公式與重要數字旁標 `<span class="tg must">要背</span>`（考試不給）、`<span class="tg derive">會推</span>`、`<span class="tg given">卷上會給</span>`。**小節裡不放標籤說明**（2026-11-12 使用者：「不用一直重複出現，甚至不應該在小節裡出現」）：說明只在化學首頁「怎麼使用」，讀者點標籤會顯示一行意思。同一條公式只在第一次出現時標「要背」，之後指回去。
6. **每個公式框都是三層：公式 → 中文版公式 → 符號表**（2026-11-07 使用者：「第一次的使用者還是看不懂，各個代數的中文沒有列出來」）。
   - 中文版公式：每個符號換成中文名稱，例：E = hν 下面寫「單光子能量 = 普朗克常數 × 頻率」。
   - 符號表（`table.tbl.sym2`）：列出公式裡的**每一個**符號，欄位是「符號、中文、單位、數值」，前面介紹過的也再列一次，不用讀者往回找。
   - 寫法：`<div class="eqb"><p class="eq">公式＋標籤</p><p class="eqzh">中文版公式</p><table class="tbl sym2">…</table></div>`。
   - 課文裡順帶出現的公式（例：反過來求 λ = hc/E）也在後面括號寫中文版。
7. **常數用同一套說法**（2026-11-07 使用者確認，以普朗克常數為範本）：
   - **它是哪兩個量之間的換算係數**（例：h 把頻率換成能量；R 把溫度和莫耳數換成 PV 的能量；Nₐ 把「一個」換成「一莫耳」；c 把波長換成頻率）。
   - **哪一部分是自然規律**：實驗發現的正比關係，而且對所有情況都是同一個比例（例：光子能量和頻率成正比）。
   - **數字為什麼這麼大或這麼小**：是單位造成的；換一組貼近的單位示範，數字就變普通（例：h 用 J、Hz 是 6.63 × 10⁻³⁴，用 eV 和 10¹⁵ Hz 約 4.14，綠光 0.55 → 2.3 eV）。
   - 最後才說數值、要背還是卷上會給；歷史只用一句帶過。符號表裡常數的中文寫成「○○常數：把 A 換成 B 的換算係數」。
   - 其他數字（13.6、0.529、1240、119,600、0.0821、8.314…）也要說它從哪裡來（實驗值，或由哪些常數換算）；乘數與次方（× Z²、÷ n²）用一句話說明為什麼是這個形式；由別的數字推出來的（pH + pOH = 14 來自 Kw）要寫出推導。
8. **捷徑數字用單位換算互動圖推出**（`unitChain`：讀者自己選比例、可翻轉，不是固定步驟），消掉的單位畫刪除線。
9. **比較題教讀法**：「分數上面是正比、下面是反比」，並用一個真實情況示範常數會消掉（例：He⁺ 的游離能是氫的幾倍）。
10. **意思相同的公式並排對照**（例：光 λ = hc/E、電子 λ = h/(mv)，都是 λ = h ÷ 某個量）。
11. **公式長在圖上**：公式的每一項都對應圖上看得到的東西（同一個顏色），數值跟著圖即時代入。

## 4. 什麼時候做互動圖

符合任一條就要有讀者自己操作的圖：
1. **公式**：每條「要背」或「會推」的公式，至少有一張圖能改變它的變數，結果立刻顯示。
2. **看不見的東西**：波、電子、軌域、節點、分子形狀、立體構型、遮蔽。
3. **會隨條件或時間改變的過程**：滴定、反應進行、機構步驟、平衡移動、躍遷。
4. **要比較或排序的一組東西**：能切換、並排比較（譜線系、沸點、酸性、鍵角）。

不做圖：定義與名稱、歷史、純記憶清單（人名、俗名、焰色）、單一數字。可以保留文字的：純記憶的名稱清單、一行總整理。

## 5. 互動圖怎麼設計

1. **先現象、後規則**：先讓讀者在圖上看到現象，規則要能從圖推出來。
2. **一張圖一個觀念**，複雜的拆成好幾張。
3. **互動要有理由**：操作是為了回答課文剛提出的問題（例：光電效應圖回答「顏色還是亮度決定打不打得出電子」）。不做「點一下展開公式」這種讀者不知道為什麼要點的操作。不做自動播放的動畫。
4. **圖裡的數值不能比定義先出現**：課文還沒定義的量，圖上不顯示（例：第一章第 2 節的波長圖只顯示頻率，光子能量等講完光電效應才出現）。
5. **畫法順序：課本插圖的樣子 → 立體的用可旋轉 3D（`R3D`）→ 狀態用顏色**。軌域畫成實心形狀，不用機率點雲。共用元件：`R3D`、`orbMesh`、`orbitalChart`、`unitChain`。
6. **原因畫在圖上**：並排比較、連線、標色（例：例外用「照順序 vs 實際」兩張軌域圖），不要只寫一句話。文中每個「因為／所以／比較」都要在圖上指得出來。
7. **要比較的東西同時出現**（例：4s 與 3d 一直同時畫出來）。
8. **拖動要看得到變化**：被操作的量必須讓圖形改變，不可用相對單位把變化抵銷；一打開就要看得出在比什麼（例：右邊的箱子預設 2 倍長）。
9. **只放考試需要的精確度**：考高低、比例、趨勢就只畫那些；不放考試不用的實驗數值。
10. **選到的東西一定在圖上、有明顯的標籤**：圖的範圍跟著選項走；起點、終點、選取的線都有文字標籤；目前選取的元素加 `data-cur="說明"`。照比例畫但擠在一起時，保留比例、放大選取的那段並說明。
11. **課本記號是寫法**：方格 ↑↓、組態字串旁邊要有它代表的真實東西，兩者同步。
12. **底色不能像資料**：連續的色帶用漸層，不用一條條小方塊。

## 6. 版面與視覺

1. **每張圖的說明緊貼在圖的上方**：說明要操作什麼、看什麼，接著用 `[[w:圖名]]` 把圖放在這段後面，圖下面再寫從圖看到的規則。不寫「第一張圖／第二張圖」。
2. **控制項**：每一組用 `ctl(標籤, 選項)` 包成一個單位；按鈕組用 `seg()`／`segX()`。會隨其他選擇改變的選項一律顯示最大數量，不能選的變灰。
3. **數值卡**：用共用的 `.cards`；標題和數值放不下時換行，不可切掉；數值用 3 位有效數字；數字太長就把單位移到標題，避免拖動時卡片高度跳動；卡片數量不可增減（沒有值顯示「—」）。
4. **同一個東西在不同地方用同一個顏色**（例：λ、ν、E 在圖、卡片、公式裡同色）；能量升高用紅、降低用藍。
5. **整體和成分不用同一種樣式**（例：錯離子在方括號框裡、外界離子在框外）。
6. **手機寬度（360–390px）也要看得清楚**；寬圖拆成上下兩張。深色模式下有填色的圓或方塊，文字顏色要固定。

## 7. 頁面結構與導覽

1. **一節一頁**：章節 id 加進 `app.js` 的 `PAGED`。
   - **章概覽頁**：小節清單（每節顯示練習幾題做過）、「從第 n 節開始／繼續」、按過「還不太懂」的節列成連結。
   - **小節頁**：頁首下方一行「章名・第 k / n 節」→ 課文與圖 →「讀完這一節了嗎？看懂了／還不太懂」（`READ_ON`）→ 這一節的練習 → 頁尾「下一節」按鈕。
   - **綜合練習**：只有跨好幾節的題目才放這裡，沒有就不出現。
2. **頁首**：返回一律回上一層（小節 →「‹ 章名」、章與錯題複習 →「‹ 後中化學」、化學首頁 →「‹ 學習階梯」）；「☰ 章節」是唯一的章節清單（含錯題複習、練習紀錄）；進度只顯示「本頁 x / y 題」與「跳過 n 題 ↓」，沒有題目的頁面不顯示。
3. 不加重複的入口：不另做「換章」下拉、頂端的上一節／下一節、手動「標記為完成」（章末題全部答對過時自動記錄）。

## 8. 題目

1. **每題屬於一節**：題目寫 `s: 第幾節`；讀完一節馬上練習。每節頁面先顯示 3 題（章末基本題優先），其餘摺起來，頁首的題數包含摺起的題目。
2. **兩種題目**：章末「確認理解」檢查本章觀念；「歷屆考題相似題」依歷屆題的考法自己出題，換掉化合物和數字，不轉載原題，題目上標「仿 學校 學年 第 X 題」。有對應的圖時加「在圖上看」。
3. **選項不可提示答案（S7）**：同一組選項的長短、形式、詳細程度要相近，正解不可是唯一最長（1.3 倍以上）；括號說明要嘛每個都有、要嘛都沒有。修正時把誤答寫得一樣具體但確定錯，不可把正解改含糊。
4. **解析與拆解步驟也要完整推導**，不跳步、不出現沒教過的名詞；提到例外要給原因。
5. **拆解步驟（一步一步來）**：需要推理或計算的題目，在 `src/chem/st/章id.js` 寫 `STEPS[章id] = { "q或x:識別碼": [[問題, 正解, 誤1, 誤2, 說明], ...] }`。每步只問一個小判斷，順序就是解題思路；答錯主題目時自動打開，步驟答錯只說「再想想」。純記憶題不寫。工具：`node tools/chem/dumpq.js 章id`、`node tools/chem/addst.js 章id 檔案`。
6. **題目識別碼與練習紀錄**：紀錄用「章節 id + 題型 + 題目文字的雜湊」對應題目並存文字快照，增刪重排都不會錯位。只改錯字、或把題目搬到別章時，加 `id: '原本的識別碼'` 保留步驟對應（識別碼列在 `tests/chem/qids.txt`）。同一章內題型相同的題目文字不能重複。登入後紀錄與雲端取聯集；本機最多 20000 筆。

## 9. 正確性

- 數據要有來源（教科書、CRC、OpenStax 等）；不確定的寧可不寫。
- 會隨教科書不同而略有差異的數值，標「約」或註明來源。

## 10. 測試與發佈

1. `bash tests/chem/smoke.sh`（電腦寬度）與 `SMOKE_W=390 bash tests/chem/smoke.sh`（手機寬度）都通過；`ONLY=章節id` 只測一章。檢查所有按鈕、文字不重疊、不超出圖框、名詞有連結、沒有錯誤。
2. 改完的章節 id 加進 `tests/chem/strict.txt`，會再檢查：拖動時數值卡不跳、文字不截斷、控制項分組、選項數量固定、`data-cur` 在圖上、步驟選項不提示答案（`node tests/options.test.js`）。
3. `bash tests/chem/publish.sh "說明"`（跑完全部測試、commit、push）。回報時說明改了什麼、測了什麼，並提醒手機上第一次打開可能是舊版（關掉再開一次）。預覽版（Artifact）不能更新時要明說。
4. 更新 `章節檢查表.md` 該章的每一欄。
